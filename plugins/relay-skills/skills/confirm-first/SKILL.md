# 시작 전 해석 확인

이 스킬은 요청을 잘못 이해하고 먼저 구현하는 일을 막는다. 사용자의 승인을 받기 전에는 어떤 파일도 만들거나 고치지 않는다.

## 규칙
- 읽기(파일 읽기, 검색)는 해도 된다. 쓰기, 삭제, 이름 변경, 커밋, 설치는 하지 않는다.
- 설계, 화면 배치, 구조, 모델 선택은 내가 정하지 않는다. 선택지가 있으면 선택지로 적고 사용자가 고르게 한다.
- 확인 요약은 아래 형식 그대로, 15줄 안에 쓴다.
- 확인 질문은 최대 2개다. 사용자가 한 번에 답할 수 있는 질문만 쓴다.

## 순서
1. 요청과 관련된 파일을 필요한 만큼만 읽는다.
2. 아래 형식으로 확인 요약을 쓴다.
3. 사용자의 답을 기다린다. 답이 오기 전에는 다음 단계로 가지 않는다.
4. 승인을 받으면 승인된 범위만 작업한다. 범위가 넓어지면 멈추고 다시 확인한다.

## 확인 요약 형식
```
## 이렇게 이해했어요
<요청을 내 말로 1~2문장>

## 건드릴 것
- <파일 또는 영역>

## 건드리지 않을 것
- <파일 또는 영역>

## 가정 (틀리면 알려 주세요)
- <내가 정한 가정 — 모르면 "모름"이라고 적는다>

## 선택이 필요한 것
1. <선택지 A / B> — <내 추천과 이유 한 줄>

## 끝났다고 말하려면
- <확인할 수 있는 완료 조건, 실행할 명령 포함>

이대로 진행할까요?
```
