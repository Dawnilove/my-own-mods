# 인계 요약 만들기

다음 세션이 이 세션의 대화를 보지 않고도 바로 이어서 일할 수 있게, 인계 파일 하나를 만든다.

## 규칙
- 파일을 고치거나 커밋하지 않는다. 인계 파일 하나만 쓴다.
- "완료"는 이 세션에서 실제로 실행한 명령의 결과를 본 것만 적는다. 명령과 결과 한 줄을 같이 적는다.
- 실행하지 않았거나 결과를 못 본 것은 "미확인"에 적는다. 추측으로 "되었을 것"이라고 적지 않는다.
- 같은 종류의 증거는 한 줄로 묶는다. 예: 시험이 세 곳이면 "`claude plugin test` → edit-guard 8, relay-band 4, agent-panel 3 모두 통과" 한 줄이다. 40줄을 넘기지 않기 위해서다.
- 모르는 것은 모른다고 적는다.
- 문장은 짧게, 한 문장에 한 가지만 쓴다.

## 순서
1. 이 세션에서 한 일을 되짚는다. 필요하면 `git status`와 `git diff --stat`을 실행해 변경 파일을 확인한다.
2. 하위 에이전트나 자식 세션이 아직 실행 중인지 확인한다. 이 앱에서 쓸 수 있으면 `list_sessions`(linked: true)로 본다. 실행 중이면 인계 파일에 적고, 보관하지 말라고 적는다.
3. 현재 폴더에 `인계_YYYY-MM-DD_HHMM.md` 파일을 만든다. 아래 형식을 지킨다. 40줄을 넘기지 않는다.
4. 파일 경로와 3줄 요약만 사용자에게 알린다.

## 인계 파일 형식
```
# 인계: <한 줄 제목>

## 목표
<이 작업이 끝났을 때의 모습, 1~2문장>

## 완료 (증거 있음)
- <한 일> — `<실행한 명령>` → <결과 한 줄>

## 미완료
- <남은 일> — <막힌 이유 또는 다음 행동>

## 미확인
- <실행하지 않았거나 결과를 못 본 것>

## 변경 파일
- <경로> — <무엇을 바꿨는지 한 줄>

## 다음 세션의 첫 행동
1. <가장 먼저 할 일 하나>

## 노력 수준·모델 제안
- <다음 작업 종류와 권장 노력 수준>

## 주의
- 실행 중인 자식 세션: <있음/없음/확인 못 함>
- 결정이 필요한 것: <사용자에게 물어야 할 것>
```
